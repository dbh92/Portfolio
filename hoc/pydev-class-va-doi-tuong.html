Class và đối tượng trong Python: __init__, self, thuộc tính

Lập trình hướng đối tượng từ đầu: class, đối tượng, __init__, self, phương thức, thuộc tính lớp và khi nào thật sự cần class.

Học xong bài này, bạn sẽ

  • Viết class có __init__, thuộc tính và phương thức
  • Phân biệt thuộc tính đối tượng và thuộc tính lớp
  • Biết khi nào nên dùng class thay vì hàm và dict

  2. 2. Bảo vệ tính đúng đắn của dữ liệu

Đến giờ bạn mô tả một tài khoản ngân hàng bằng dict {"chu": "An", "so_du": 500000} và viết các hàm rời rạc thao tác trên dict đó. Cách này ổn với chương trình nhỏ, nhưng khi dữ liệu và hành vi nhiều lên, bạn dễ gọi nhầm hàm, sửa sai khóa, quên kiểm tra. Lập trình hướng đối tượng (OOP) gom dữ liệu và các hàm thao tác trên dữ liệu đó vào một chỗ: class.

1. Class là bản thiết kế, đối tượng là sản phẩm

class TaiKhoan:
    """Tài khoản ngân hàng đơn giản."""

    def __init__(self, chu: str, so_du: int = 0):
        self.chu = chu            # thuộc tính của đối tượng
        self.so_du = so_du

    def nap(self, so_tien: int) -> None:     # phương thức
        self.so_du += so_tien

    def mo_ta(self) -> str:
        return f"{self.chu}: {self.so_du:,}đ"


tk_an = TaiKhoan("An", 500_000)    # tạo đối tượng: Python gọi __init__
tk_binh = TaiKhoan("Bình")
tk_an.nap(200_000)
print(tk_an.mo_ta())
print(tk_binh.mo_ta())
print(type(tk_an), isinstance(tk_an, TaiKhoan))
An: 700,000đ
Bình: 0đ
<class '__main__.TaiKhoan'> True
  • class TenLop: định nghĩa lớp. Tên lớp viết kiểu CapWords (mỗi từ viết hoa chữ đầu), khác với tên hàm, tên biến.
  • __init__ là phương thức khởi tạo, chạy tự động khi tạo đối tượng TaiKhoan(...). Nó gán các thuộc tính ban đầu.
  • self là chính đối tượng đang được gọi. Khi viết tk_an.nap(200_000), Python thực chất gọi TaiKhoan.nap(tk_an, 200_000): self chính là tk_an.
  • Mỗi đối tượng có bộ thuộc tính riêng: nạp tiền cho An không ảnh hưởng Bình.

2. Bảo vệ tính đúng đắn của dữ liệu

Lợi ích lớn nhất của class: các quy tắc nằm cạnh dữ liệu. Không ai có thể rút quá số dư nếu mọi thao tác đi qua phương thức:

class TaiKhoan:
    def __init__(self, chu: str, so_du: int = 0):
        if so_du < 0:
            raise ValueError("Số dư ban đầu không được âm")
        self.chu = chu
        self._so_du = so_du
        self._lich_su: list[tuple[str, int]] = []

    def nap(self, so_tien: int) -> None:
        if so_tien <= 0:
            raise ValueError("Số tiền nạp phải dương")
        self._so_du += so_tien
        self._lich_su.append(("nạp", so_tien))

    def rut(self, so_tien: int) -> None:
        if so_tien <= 0:
            raise ValueError("Số tiền rút phải dương")
        if so_tien > self._so_du:
            raise ValueError(f"Không đủ số dư ({self._so_du:,}đ)")
        self._so_du -= so_tien
        self._lich_su.append(("rút", so_tien))

    def so_du(self) -> int:
        return self._so_du

    def lich_su(self) -> list[tuple[str, int]]:
        return list(self._lich_su)          # trả bản sao, bên ngoài sửa không ảnh hưởng


tk = TaiKhoan("Chi", 1_000_000)
tk.nap(500_000)
tk.rut(300_000)
try:
    tk.rut(5_000_000)
except ValueError as loi:
    print("Từ chối:", loi)
print(tk.so_du(), tk.lich_su())
Từ chối: Không đủ số dư (1,200,000đ)
1200000 [('nạp', 500000), ('rút', 300000)]

Dấu gạch dưới đầu tên (_so_du) là quy ước trong Python: "thuộc tính nội bộ, đừng đụng từ bên ngoài". Python không cấm, nhưng mọi lập trình viên Python đều hiểu và tôn trọng quy ước này. Ở bài sau, bạn sẽ dùng @property để đọc tk.so_du như thuộc tính mà vẫn chặn được việc gán bậy.

3. Thuộc tính của lớp và thuộc tính của đối tượng

class SanPham:
    VAT = 0.08                 # thuộc tính lớp: dùng chung cho mọi đối tượng
    so_luong_tao = 0

    def __init__(self, ten: str, gia: int):
        self.ten = ten         # thuộc tính đối tượng: riêng từng cái
        self.gia = gia
        SanPham.so_luong_tao += 1

    def gia_sau_thue(self) -> int:
        return round(self.gia * (1 + self.VAT))


a = SanPham("Bút", 10_000)
b = SanPham("Vở", 15_000)
print(a.gia_sau_thue(), b.gia_sau_thue(), SanPham.so_luong_tao)
10800 16200 2

Thuộc tính lớp hợp cho hằng số và bộ đếm dùng chung. Khi đọc self.VAT, Python tìm trong đối tượng trước, không thấy thì tìm lên lớp.

Đừng đặt list hay dict làm thuộc tính lớpViết class GioHang: mat_hang = [] thì mọi giỏ hàng dùng chung một list: thêm hàng vào giỏ này, giỏ khác cũng thấy. Đây là cùng một bẫy với tham số mặc định là list ở chặng 2. Thuộc tính thay đổi được luôn tạo trong __init__: self.mat_hang = [].

4. Khi nào nên viết class?

Không phải mọi thứ đều cần class. Python rất thoải mái với hàm và dict. Dùng class khi:

  • Có dữ liệu đi kèm quy tắc phải luôn đúng (số dư không âm, đơn hàng đã giao không được sửa).
  • Có trạng thái thay đổi theo thời gian và nhiều thao tác trên trạng thái đó (giỏ hàng, kết nối, trò chơi).
  • Cần nhiều biến thể cùng giao diện (gửi thông báo qua email hay SMS): bài kế thừa sẽ nói kỹ.

Một class chỉ có __init__ và một phương thức khác thường nên là một hàm. Một class chỉ chứa dữ liệu, không có hành vi, thì dùng dataclass (bài 4 của chặng này).

Tóm tắt

  • class TenLop:, __init__(self, ...) gán thuộc tính; phương thức luôn nhận self đầu tiên.
  • Đặt quy tắc kiểm tra trong phương thức để dữ liệu luôn hợp lệ; _ten là quy ước "nội bộ".
  • Thuộc tính lớp dùng chung; thuộc tính thay đổi được tạo trong __init__.
  • Dùng class khi có dữ liệu + quy tắc + trạng thái; không thì hàm là đủ.

Bài tập

Bài 1. Tài khoản có lịch sử

Viết lại lớp TaiKhoan ở mục 2 mà không nhìn bài, chạy kịch bản: mở với 1.000.000đ, nạp 500.000đ, rút 2.000.000đ (phải bị từ chối), rút 300.000đ; in số dư và lịch sử.

Xem gợi ý

So sánh kết quả với ví dụ ở mục 2: số dư cuối 1.200.000đ, lịch sử gồm đúng hai giao dịch. Lần rút bị từ chối không được ghi vào lịch sử, vì raise nằm trước dòng append.

Bài 2. Giỏ hàng

Viết lớp GioHang với them(ten, gia, so_luong=1) (thêm trùng tên thì cộng số lượng), xoa(ten), tong_tien() và so_mat_hang().

Xem đáp án 
class GioHang:
    def __init__(self):
        self._hang: dict[str, dict] = {}

    def them(self, ten: str, gia: int, so_luong: int = 1) -> None:
        if so_luong <= 0 or gia < 0:
            raise ValueError("Giá và số lượng không hợp lệ")
        if ten in self._hang:
            self._hang[ten]["so_luong"] += so_luong
        else:
            self._hang[ten] = {"gia": gia, "so_luong": so_luong}

    def xoa(self, ten: str) -> None:
        if ten not in self._hang:
            raise KeyError(f"Không có '{ten}' trong giỏ")
        del self._hang[ten]

    def tong_tien(self) -> int:
        return sum(m["gia"] * m["so_luong"] for m in self._hang.values())

    def so_mat_hang(self) -> int:
        return len(self._hang)


gio = GioHang()
gio.them("Áo thun", 150_000, 2)
gio.them("Quần jean", 450_000)
gio.them("Áo thun", 150_000)
gio.xoa("Quần jean")
print(gio.so_mat_hang(), f"{gio.tong_tien():,}đ")
1 450,000đ

Dữ liệu bên trong là dict tên → thông tin; bên ngoài chỉ thấy các phương thức. Sau này đổi cách lưu (ví dụ sang list hoặc CSDL), code dùng GioHang không phải sửa gì.

Nguồn tham khảo: Python Tutorial: Classes; PEP 8: Naming Conventions.

Bài tập thực hành

  1. Viết lớp TaiKhoan có nap(), rut(), lich_su; rút quá số dư thì raise ValueError.
  2. Viết lớp GioHang có them(ten, gia, so_luong), tong_tien() và xoa(ten).

Làm xong bài tập mới chuyển sang bài tiếp theo: tự viết code là cách duy nhất để nhớ lâu.
