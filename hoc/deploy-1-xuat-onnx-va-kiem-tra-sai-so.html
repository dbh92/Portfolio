Ở dự án "Phân loại ảnh OK/NG bằng transfer learning với PyTorch", bước cuối là một dòng torch.onnx.export. Dòng đó tạo ra file, nhưng chưa chứng minh file đó cho cùng kết quả với mô hình bạn đã đánh giá. Trên máy tính công nghiệp, mô hình sẽ chạy bằng ONNX Runtime (trong Python, C# hay C++), với một đoạn tiền xử lý viết lại ở nơi khác. Chỉ cần một chi tiết lệch (quên model.eval(), đảo kênh màu, quên chuẩn hóa) là tỷ lệ lọt lỗi tăng vọt mà không có thông báo lỗi nào. Bài này dạy quy trình xuất ONNX có kiểm chứng: xuất, kiểm tra file, chạy bằng ONNX Runtime, so sánh số với PyTorch trên nhiều ảnh, và lưu một "thẻ mô hình" (model card) đi kèm file. Đây là bài mở đầu chặng Deployment; bài sau đưa đúng file này vào ứng dụng C#.

Mục tiêu cuối bàiXuất được mô hình PyTorch (và YOLO) sang ONNX với batch động; chạy suy luận bằng ONNX Runtime trong Python; chứng minh bằng số rằng ONNX cho cùng kết quả với PyTorch trên N ảnh; đóng gói file ONNX kèm thẻ mô hình JSON (đặc tả đầu vào, opset, mã băm).

1. Quy trình: từ file .pt tới file .onnx "đã kiểm chứng"

ONNX (Open Neural Network Exchange) là định dạng file mô tả đồ thị tính toán của mạng nơ-ron (các phép Conv, Relu, Gemm…) cùng trọng số. Nhiều runtime đọc được ONNX: ONNX Runtime (CPU, GPU, DirectML), OpenVINO, TensorRT. Mỗi phiên bản bộ phép toán gọi là một opset; runtime cũ chỉ hiểu tới một opset nhất định, nên opset là thông tin bắt buộc phải ghi lại.

Mô hình đã huấn luyện (.pt)
   │ 1. model.eval()
   │ 2. torch.onnx.export(...)            → ok_ng.onnx
   │ 3. onnx.checker + in đầu vào/đầu ra   → đúng tên, shape, kiểu?
   │ 4. ONNX Runtime chạy N ảnh thật       → so với PyTorch: sai số, tỷ lệ khớp quyết định
   │ 5. Lưu bộ ảnh vàng + kết quả mong đợi → để kiểm tra phía C#/C++
   └ 6. Thẻ mô hình JSON (opset, tiền xử lý, ngưỡng, SHA-256)
→ Chỉ file đã qua đủ 6 bước mới được chép sang máy trạm.

2. Chuẩn bị: dữ liệu, tiền xử lý và một mô hình nhỏ

Để bài chạy trong vài giây trên mọi máy, ta tạo dữ liệu giả: tấm kim loại xám 96×96 pixel. Ảnh OK có thể có chấm mực xanh dương do QC đánh dấu (hợp lệ); ảnh NG có vết gỉ màu cam. Hai loại chỉ khác nhau ở màu, nên thứ tự kênh màu rất quan trọng, giống hệt nhiều bài toán thật (dây điện sai màu, nhãn sai màu, vết cháy).

Điểm quan trọng nhất của mục này là hàm tien_xu_ly(): mọi nơi chạy mô hình (huấn luyện, kiểm tra ONNX, ứng dụng trạm) phải làm đúng y các bước này.

import cv2
import numpy as np
import torch
import torch.nn as nn

torch.manual_seed(0)
torch.set_num_threads(4)


def tao_anh(ng, rng):
    """Tấm kim loại 96x96 (BGR). OK có thể có chấm mực xanh của QC, NG có vết gỉ màu cam."""
    anh = np.full((96, 96, 3), 128, np.float32) + rng.normal(0, 8, (96, 96, 3))
    anh += np.linspace(-15, 15, 96)[None, :, None]            # ánh sáng không đều trái-phải
    tam = tuple(int(v) for v in rng.integers(20, 76, 2))
    r = int(rng.integers(5, 10))
    if ng:
        cv2.circle(anh, tam, r, (40, 110, 200), -1)           # gỉ: cam (B thấp, R cao)
    elif rng.random() < 0.6:
        cv2.circle(anh, tam, r, (200, 120, 40), -1)           # mực QC: xanh dương
    return np.clip(anh, 0, 255).astype(np.uint8)


KICH_THUOC = 64
MEAN = np.array([0.485, 0.456, 0.406], np.float32)           # mean/std ImageNet, theo thứ tự R, G, B
STD = np.array([0.229, 0.224, 0.225], np.float32)


def tien_xu_ly(anh_bgr):
    """Ảnh BGR uint8 (H, W, 3) -> float32 (3, 64, 64), đúng như lúc huấn luyện."""
    anh = cv2.resize(anh_bgr, (KICH_THUOC, KICH_THUOC), interpolation=cv2.INTER_AREA)
    anh = cv2.cvtColor(anh, cv2.COLOR_BGR2RGB).astype(np.float32) / 255.0
    anh = (anh - MEAN) / STD
    return np.ascontiguousarray(anh.transpose(2, 0, 1))      # HWC -> CHW


rng = np.random.default_rng(0)
nhan = np.array([i % 2 for i in range(800)])                 # 0 = OK, 1 = NG
anh_goc = [tao_anh(n, rng) for n in nhan]
X = torch.from_numpy(np.stack([tien_xu_ly(a) for a in anh_goc]))
y = torch.from_numpy(nhan).long()
cv2.imwrite("vi_du_ok.png", anh_goc[2])
cv2.imwrite("vi_du_ng.png", anh_goc[1])
print(X.shape, X.dtype, y[:6].tolist())
torch.Size([800, 3, 64, 64]) torch.float32 [0, 1, 0, 1, 0, 1]

Mô hình: 3 khối Conv + BatchNorm + ReLU, rồi Dropout và một lớp Linear ra 2 logit (OK, NG). Hai lớp BatchNorm và Dropout được chọn có chủ ý: chúng là lý do số một khiến người mới quên model.eval() mà gặp rắc rối. Huấn luyện 4 epoch trên 600 ảnh, giữ 200 ảnh làm tập kiểm tra:

class MangOkNg(nn.Module):
    def __init__(self):
        super().__init__()
        self.dac_trung = nn.Sequential(
            nn.Conv2d(3, 16, 3, padding=1), nn.BatchNorm2d(16), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(32, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(),
            nn.AdaptiveAvgPool2d(1), nn.Flatten())
        self.dau = nn.Sequential(nn.Dropout(0.3), nn.Linear(32, 2))

    def forward(self, x):
        return self.dau(self.dac_trung(x))


model = MangOkNg()
opt = torch.optim.Adam(model.parameters(), lr=3e-3)
for ep in range(4):
    model.train()
    perm = torch.randperm(600)
    for i in range(0, 600, 32):
        idx = perm[i:i + 32]
        loss = nn.functional.cross_entropy(model(X[idx]), y[idx])
        opt.zero_grad()
        loss.backward()
        opt.step()
    model.eval()
    with torch.no_grad():
        acc = (model(X[600:]).argmax(1) == y[600:]).float().mean().item()
    print(f"epoch {ep + 1}: loss {loss.item():.3f}, val acc {acc:.3f}")

torch.save(model.state_dict(), "ok_ng.pt")

Giá trị loss có thể lệch chút ít trên CPU hoặc phiên bản thư viện khác. Bài toán giả này dễ nên độ chính xác đạt 100%; với mô hình thật của bạn (ví dụ ResNet18 ở dự án transfer learning), quy trình phía dưới giữ nguyên, chỉ thay MangOkNg và tien_xu_ly.

3. model.eval(): một dòng quyết định kết quả

Hai loại lớp hoạt động khác nhau giữa lúc huấn luyện (train()) và lúc suy luận (eval()):

LớpChế độ trainChế độ eval
BatchNormChuẩn hóa bằng mean/var của batch hiện tại, đồng thời cập nhật running_mean/running_varDùng running_mean/running_var đã học, cố định
DropoutNgẫu nhiên tắt 30% nơ-ron mỗi lần chạyKhông làm gì (cho qua)

Hãy xem điều gì xảy ra nếu chạy suy luận ở chế độ train. Dùng một bản sao để không làm hỏng model:

import copy

torch.manual_seed(0)                      # để Dropout cho cùng kết quả mỗi lần chạy bài
anh_ok = X[600:601]                       # ảnh 600 là ảnh OK (nhãn 0)
ban_sao = copy.deepcopy(model)

with torch.no_grad():
    ban_sao.eval()
    print("eval , lần 1:", ban_sao(anh_ok).numpy().round(3))
    print("eval , lần 2:", ban_sao(anh_ok).numpy().round(3))
    ban_sao.train()
    print("train, lần 1:", ban_sao(anh_ok).numpy().round(3))
    print("train, lần 2:", ban_sao(anh_ok).numpy().round(3))
    ban_sao.eval()
    print("eval sau khi lỡ chạy train:", ban_sao(anh_ok).numpy().round(3))

Ba bài học từ năm dòng này:

  • Ở chế độ train, lần chạy đầu phân loại ảnh OK thành NG (logit NG lớn hơn logit OK): BatchNorm chuẩn hóa bằng thống kê của đúng một ảnh, hoàn toàn khác thống kê đã học.
  • Cùng một ảnh, hai lần chạy cho hai kết quả khác hẳn nhau (lần hai lại ra OK): Dropout ngẫu nhiên. Mô hình kiểm tra mà không tái lập được kết quả là không thể nghiệm thu.
  • Chỉ chạy ở chế độ train (kể cả trong torch.no_grad()) cũng đã sửa running_mean/running_var: dòng cuối khác dòng đầu. Nếu sau đó bạn lưu mô hình, bạn lưu một mô hình đã bị làm hỏng.
Quên eval() khi xuất và khi so sánhNếu gọi torch.onnx.export khi mô hình đang ở chế độ train, torch 2.14 in cảnh báo UserWarning: Exporting a model while it is in training mode... Calling model.eval() before export is recommended. Trong thử nghiệm với torch 2.14, file ONNX tạo ra vẫn dùng thống kê đã học, nhưng hành vi này phụ thuộc phiên bản và exporter, đừng dựa vào nó. Bẫy hay gặp hơn nằm ở phía so sánh: chạy PyTorch tham chiếu ở chế độ train, thấy sai khác lớn rồi kết luận nhầm là "ONNX bị lỗi". Quy tắc: gọi model.eval() ngay sau khi nạp trọng số, trước mọi việc khác.

4. Xuất ONNX bằng torch.onnx.export

Từ PyTorch 2.9, torch.onnx.export mặc định dùng exporter mới dựa trên torch.export (tham số dynamo=True). Exporter này cần gói onnxscript, trả về một đối tượng ONNXProgram và, nếu bạn truyền tên file, ghi luôn file. Lệnh xuất đầy đủ cho mô hình phân loại:

model = MangOkNg()
model.load_state_dict(torch.load("ok_ng.pt", weights_only=True))
model.eval()                                            # luôn luôn, trước khi xuất

vi_du = torch.from_numpy(tien_xu_ly(anh_goc[0]))[None]  # (1, 3, 64, 64), đi qua đúng tiền xử lý
chuong_trinh = torch.onnx.export(
    model, (vi_du,), "ok_ng.onnx",
    input_names=["images"], output_names=["logits"],
    dynamic_shapes={"x": {0: "batch"}},                 # "x" = tên tham số của forward(); trục 0 động
    opset_version=18,
    external_data=False,                                # trọng số nằm luôn trong file .onnx
    verbose=False,                                      # tắt các dòng tiến trình [torch.onnx] ...
)
print(type(chuong_trinh).__name__)

from pathlib import Path
for p in sorted(Path(".").glob("ok_ng*")):
    print(p.name, p.stat().st_size, "byte")

Ý nghĩa từng tham số (đã kiểm tra trên mã nguồn torch 2.14.1):

Tham sốGiá trị trong bàiGhi chú
args(vi_du,)Tuple đầu vào mẫu. Dùng một ảnh thật đã qua tiền xử lý, không cần đúng batch bạn sẽ chạy.
input_names, output_namesimages, logitsTên mà ứng dụng C#/Python sẽ dùng khi gọi run. Đặt tên rõ ràng, ghi vào thẻ mô hình.
dynamic_shapes{"x": {0: "batch"}}Cách khai báo trục động của exporter mới. Khóa là tên tham số của forward, giá trị là {chỉ số trục: tên trục}. Không khai báo thì mọi trục cố định theo ví dụ (batch = 1).
dynamic_axes(không dùng)Cách cũ, khóa là tên đầu vào/đầu ra. Với exporter mới vẫn chạy nhưng in UserWarning và tự chuyển sang dynamic_shapes; chỉ nên dùng với dynamo=False.
opset_version18Mặc định là 20 trong torch 2.14. Chọn theo runtime đích: runtime cũ trên máy trạm có thể chưa hỗ trợ opset mới. Exporter mới làm việc ở opset 18; chọn thấp hơn 18 thì nó in cảnh báo và thử chuyển đổi phiên bản, có thể không thành công.
external_dataFalseMặc định là True: trọng số được ghi ra file riêng ok_ng.onnx.data cạnh file .onnx. Với mô hình dưới 2 GB (gần như mọi mô hình vision), đặt False để có một file duy nhất.
dynamo(mặc định True)dynamo=False dùng exporter TorchScript cũ, đã bị đánh dấu deprecated (in DeprecationWarning).
verify(không dùng)verify=True cho exporter tự chạy thử bằng ONNX Runtime trên đầu vào mẫu. Tiện, nhưng chỉ một đầu vào; không thay được phép so sánh trên N ảnh ở mục 7.
Bẫy file .onnx.dataVới cài đặt mặc định (external_data=True), exporter tạo hai file. Chép mỗi model.onnx sang máy trạm thì ONNX Runtime báo lỗi không tìm thấy dữ liệu trọng số. Hoặc đặt external_data=False, hoặc luôn chép cả hai file và ghi cả hai mã băm vào thẻ mô hình.

Để so sánh, đây là cách viết cho exporter cũ mà bạn sẽ gặp trong nhiều hướng dẫn trên mạng. Nó vẫn chạy trong torch 2.14 (kèm cảnh báo deprecated), cho cùng đồ thị đầu vào với batch động:

import warnings

import onnx

with warnings.catch_warnings():
    warnings.simplefilter("ignore", DeprecationWarning)

  • Định dạng đầu ra khác nhau theo đời mô hình: YOLOv8/YOLO11 xuất tensor thô cần NMS; YOLO26 là end-to-end nên đầu ra đã là danh sách khung cuối cùng (tọa độ, điểm tin cậy, lớp). Luôn in get_outputs() như trên trước khi viết code giải mã, đừng chép code giải mã của đời khác.
  • So sánh theo khung, không theo mảng: hai phía có thể trả khung theo thứ tự khác nhau. Ghép cặp khung theo IoU (Intersection over Union, tỷ lệ diện tích giao trên diện tích hợp) rồi so lớp và điểm tin cậy.

Hàm ghép cặp khung dưới đây chạy được ngay, dùng cho mọi mô hình phát hiện vật (YOLO, hay mô hình của bạn):

def iou(a, b):
    """a, b: [x1, y1, x2, y2]"""
    rong = max(0.0, min(a[2], b[2]) - max(a[0], b[0]))
    cao = max(0.0, min(a[3], b[3]) - max(a[1], b[1]))
    giao = rong * cao
    hop = (a[2] - a[0]) * (a[3] - a[1]) + (b[2] - b[0]) * (b[3] - b[1]) - giao
    return giao / hop if hop > 0 else 0.0


def so_khop_khung(ds_ref, ds_moi, iou_min=0.9, lech_diem_max=0.02):
    """Mỗi phần tử: (x1, y1, x2, y2, diem, lop). Trả về danh sách vấn đề (rỗng = khớp)."""
    van_de, da_dung = [], set()
    for i, r in enumerate(ds_ref):
        tot, j_tot = 0.0, None
        for j, m in enumerate(ds_moi):
            if j not in da_dung and m[5] == r[5] and iou(r, m) > tot:
                tot, j_tot = iou(r, m), j
        if j_tot is None or tot < iou_min:
            van_de.append(f"khung ref {i} (lớp {r[5]}) không có cặp, IoU tốt nhất {tot:.2f}")
            continue
        da_dung.add(j_tot)
        if abs(ds_moi[j_tot][4] - r[4]) > lech_diem_max:
            van_de.append(f"khung ref {i}: điểm {r[4]:.3f} vs {ds_moi[j_tot][4]:.3f}")
    van_de += [f"khung mới {j} thừa" for j in range(len(ds_moi)) if j not in da_dung]
    return van_de

Sáu tháng sau, ai đó hỏi: "file ok_ng.onnx trên máy trạm 3 là bản nào, huấn luyện ngày nào, tiền xử lý ra sao, đã kiểm chứng chưa?". Câu trả lời phải nằm trong một file JSON đi cùng mô hình. Mã băm SHA-256 (dấu vân tay 64 ký tự hex của nội dung file) cho phép kiểm tra file không bị chép nhầm phiên bản hay hỏng khi truyền.

import hashlib
import platform
from datetime import datetime


def sha256(duong_dan):
    h = hashlib.sha256()
    with open(duong_dan, "rb") as f:
        for khoi in iter(lambda: f.read(1 << 20), b""):    # đọc từng 1 MB, không nạp cả file vào RAM
            h.update(khoi)
    return h.hexdigest()

def nap_mo_hinh(duong_dan_the):
    the = json.loads(Path(duong_dan_the).read_text(encoding="utf-8"))
    file_onnx = Path(duong_dan_the).parent / the["file"]
    if sha256(file_onnx) != the["sha256"]:
        raise RuntimeError(f"{file_onnx.name}: SHA-256 không khớp thẻ mô hình, từ chối nạp")
    s = ort.InferenceSession(str(file_onnx), providers=["CPUExecutionProvider"])
    vao = s.get_inputs()[0]
    if vao.name != the["dau_vao"]["ten"] or vao.shape[1:] != the["dau_vao"]["shape"][1:]:
        raise RuntimeError(f"Đầu vào {vao.name} {vao.shape} khác thẻ mô hình")
    return s, the

Bài 3. Viết hàm kiem_chung(sess, model, ds_anh, atol=1e-5) trả về dict gồm sai khác logit lớn nhất, tỷ lệ khớp quyết định, số ảnh có P(NG) trong vùng 0,4–0,6, và "dat": True/False (đạt khi sai khác ≤ atol và khớp 100%). Chạy với sess và với một model "lỡ chạy train" (bản sao đã chạy forward ở chế độ train rồi eval lại).

def kiem_chung(sess, model, ds_anh, atol=1e-5):
    model.eval()
    vao = np.stack([tien_xu_ly(a) for a in ds_anh])
    with torch.no_grad():
        r = model(torch.from_numpy(vao)).numpy()
    o = sess.run(None, {"images": vao})[0]
    p = softmax(o)[:, 1]
    kq = {"sai_khac_max": float(np.abs(o - r).max()),
          "khop": float((o.argmax(1) == r.argmax(1)).mean()),
          "sat_nguong": int(((p > 0.4) & (p < 0.6)).sum())}
    kq["dat"] = kq["sai_khac_max"] <= atol and kq["khop"] == 1.0
    return kq

Tóm tắt

  • model.eval() trước khi xuất và trước khi so sánh; chạy forward ở chế độ train làm hỏng thống kê BatchNorm ngay cả trong no_grad().
  • torch 2.14: torch.onnx.export mặc định dynamo=True (cần onnxscript), trục động khai báo bằng dynamic_shapes theo tên tham số forward, opset mặc định 20, external_data=True tạo thêm file .onnx.data.
  • onnx.checker chỉ kiểm tra cấu trúc; in get_inputs()/get_outputs() để biết "hợp đồng" của mô hình.
  • ONNX Runtime: tạo session một lần, đầu vào float32 NCHW; sai kiểu/shape thì báo lỗi, sai tiền xử lý thì không.
  • So sánh trên N ảnh: sai khác lớn nhất (FP32 CPU cỡ 10-6), assert_allclose, tỷ lệ khớp quyết định, số ảnh sát ngưỡng.
  • Tiền xử lý là nguồn sai lệch số một: một hàm dùng chung, đặc tả trong thẻ mô hình, bộ ảnh vàng PNG + logit mong đợi + tổng từng kênh.
  • YOLO: model.export(format="onnx"), in shape đầu ra trước khi giải mã, so khung bằng ghép cặp IoU.
  • Thẻ mô hình JSON (phiên bản, opset, đặc tả vào/ra, tiền xử lý, ngưỡng, SHA-256, kết quả kiểm chứng) đi cùng file ONNX; ứng dụng kiểm tra mã băm trước khi nạp.
