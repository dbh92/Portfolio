subprocess và lên lịch chạy script Python: Task Scheduler, cron

Gọi chương trình khác bằng subprocess.run, viết script chạy không giám sát và lên lịch bằng Task Scheduler trên Windows, cron trên Linux.

Học xong bài này, bạn sẽ

  • Chạy chương trình khác bằng subprocess.run an toàn
  • Lên lịch bằng Task Scheduler (Windows) và cron (Linux)
  • Viết script chạy không giám sát: đường dẫn tuyệt đối, log, mã thoát

Tự động hóa thật sự nghĩa là script chạy khi bạn không có mặt: sao lưu dữ liệu lúc 18 giờ, gửi báo cáo lúc 7 giờ sáng, dọn file tạm mỗi Chủ nhật. Bài này dạy hai việc: gọi chương trình khác từ Python bằng subprocess, và lên lịch chạy script trên Windows (Task Scheduler) và Linux (cron), cùng những nguyên tắc để script chạy không giám sát mà không gặp sự cố.

1. subprocess.run: chạy chương trình khác

import subprocess
import sys

kq = subprocess.run(
    [sys.executable, "-c", "import sys; print('Python', sys.version_info[:2]); sys.exit(3)"],
    capture_output=True,   # bắt stdout, stderr thay vì in ra màn hình
    text=True,             # nhận chuỗi thay vì bytes
    timeout=30,
)
print(kq.returncode, kq.stdout.strip())
3 Python (3, 14)
  • Truyền lệnh dưới dạng list các phần (chương trình, tham số), không ghép thành một chuỗi. Python tự xử lý dấu cách và ký tự đặc biệt trong tham số.
  • sys.executable là đường dẫn đến chính trình thông dịch Python đang chạy: dùng nó thay vì gõ "python" để chắc chắn gọi đúng môi trường ảo.
  • returncode là mã thoát (0 là thành công); stdout, stderr là output đã bắt.
  • timeout tránh treo vô hạn nếu chương trình con không kết thúc.
import subprocess
import sys

try:
    subprocess.run([sys.executable, "-c", "raise SystemExit(1)"], check=True, timeout=30)
except subprocess.CalledProcessError as e:
    print("Lệnh thất bại, mã thoát", e.returncode)

kq = subprocess.run(["git", "--version"], capture_output=True, text=True)
print(kq.stdout.split()[0])
Lệnh thất bại, mã thoát 1
git

check=True ném CalledProcessError khi mã thoát khác 0: dùng khi lỗi của chương trình con phải dừng script của bạn.

Tránh shell=True với dữ liệu từ ngoàisubprocess.run(f"ping {dia_chi}", shell=True) cho phép chuỗi lệnh đi qua shell. Nếu dia_chi đến từ người dùng và chứa ; rm -rf ~ hay & del ..., lệnh đó sẽ được thực thi. Đây là lỗ hổng "command injection". Luôn dùng dạng list; chỉ dùng shell=True với chuỗi cố định bạn tự viết.

Trước khi gọi chương trình ngoài, hãy xem Python có sẵn cách làm không: sao chép, nén file dùng shutil; tải web dùng requests. Code thuần Python chạy giống nhau trên mọi hệ điều hành, còn lệnh ngoài thì không (dir chỉ có trên Windows, ls chỉ có trên Linux, macOS).

2. Script chạy không giám sát: 5 nguyên tắc

  1. Đường dẫn tuyệt đối. Lịch chạy thường khởi động script ở một thư mục khác (ví dụ C:\Windows\System32). Mọi file của script tính từ Path(__file__).resolve().parent.
  2. Ghi log ra file, có thời gian. Không ai thấy print.
  3. Trả mã thoát đúng: 0 khi thành công, khác 0 khi lỗi, để lịch chạy ghi nhận và báo động.
  4. Chạy lại được (idempotent): chạy hai lần không tạo dữ liệu trùng, không hỏng gì. Máy tắt giữa chừng thì lần sau chạy lại là đủ.
  5. Không hỏi: không input(), mọi cấu hình qua tham số dòng lệnh, file cấu hình hoặc biến môi trường.

3. Ví dụ: script sao lưu thư mục

"""sao_luu.py: nén một thư mục thành file zip có ngày giờ, giữ N bản mới nhất."""
import argparse
import logging
import shutil
import sys
from datetime import datetime
from pathlib import Path

GOC = Path(__file__).resolve().parent
log = logging.getLogger("sao_luu")


def sao_luu(nguon: Path, dich: Path, giu: int, bay_gio: datetime) -> Path:
    dich.mkdir(parents=True, exist_ok=True)
    ten = f"{nguon.name}_{bay_gio:%Y%m%d_%H%M%S}"
    file_zip = Path(shutil.make_archive(str(dich / ten), "zip", root_dir=nguon))
    log.info("Đã tạo %s (%.1f KB)", file_zip.name, file_zip.stat().st_size / 1024)
    cac_ban = sorted(dich.glob(f"{nguon.name}_*.zip"))       # tên có ngày giờ nên sắp theo tên = theo thời gian
    for cu in cac_ban[:-giu]:
        cu.unlink()
        log.info("Xóa bản cũ %s", cu.name)
    return file_zip


def main(argv: list[str] | None = None) -> int:
    p = argparse.ArgumentParser()
    p.add_argument("nguon", type=Path)
    p.add_argument("--dich", type=Path, default=GOC / "ban_sao")
    p.add_argument("--giu", type=int, default=7)
    args = p.parse_args(argv)
    logging.basicConfig(
        level=logging.INFO, format="%(asctime)s %(levelname)s %(message)s",
        handlers=[logging.FileHandler(GOC / "sao_luu.log", encoding="utf-8"), logging.StreamHandler()],
    )
    try:
        sao_luu(args.nguon.resolve(), args.dich, args.giu, datetime.now())
    except Exception:
        log.exception("Sao lưu thất bại")
        return 1
    return 0


if __name__ == "__main__":
    sys.exit(main())

  ...

1

except Exception ở tầng ngoài cùng là chấp nhận được (chặng 3) vì nó ghi đủ traceback vào log và trả mã lỗi; không có nó, lỗi chỉ hiện ra màn hình mà lúc chạy theo lịch không ai nhìn thấy.

4. Lên lịch trên Windows: Task Scheduler

Cách nhanh bằng lệnh (PowerShell hoặc cmd), chạy 18:00 hằng ngày:

schtasks /Create /SC DAILY /ST 18:00 /TN "HocPython\SaoLuu" ^
  /TR "\"D:\du-an\sao-luu\.venv\Scripts\python.exe\" \"D:\du-an\sao-luu\sao_luu.py\" D:\tai_lieu"

schtasks /Run /TN "HocPython\SaoLuu"      <- chạy thử ngay
schtasks /Query /TN "HocPython\SaoLuu" /V /FO LIST

Hoặc dùng giao diện: mở Task Scheduler › Create Basic Task, chọn lịch, ở bước Start a program điền Program là đường dẫn python.exe trong .venv của dự án, Arguments là đường dẫn script và tham số, Start in là thư mục dự án. Trong tab Settings, bật "Run task as soon as possible after a scheduled start is missed" để máy tắt lúc 18:00 thì lần mở sau vẫn chạy bù.

Dùng python.exe trong .venv của dự án (đường dẫn tuyệt đối) để có đủ thư viện. Script không cần cửa sổ console thì dùng pythonw.exe.

5. Lên lịch trên Linux: cron

Mở bảng lịch bằng crontab -e và thêm một dòng:

# phút giờ ngày-trong-tháng tháng thứ   lệnh
0 18 * * * /home/an/sao-luu/.venv/bin/python /home/an/sao-luu/sao_luu.py /home/an/tai_lieu >> /home/an/sao-luu/cron.log 2>&1
30 7 * * 1-5  /home/an/.local/bin/uv run --project /home/an/bao-cao bao-cao   # 7:30 thứ Hai đến thứ Sáu
Biểu thứcÝ nghĩa
0 18 * * *18:00 mỗi ngày
*/15 * * * *Mỗi 15 phút
0 2 * * 02:00 sáng Chủ nhật
0 8 1 * *8:00 ngày đầu mỗi tháng

cron chạy với biến môi trường tối thiểu (PATH rất ngắn, không có các biến bạn đặt trong .bashrc), nên luôn dùng đường dẫn tuyệt đối cho cả chương trình lẫn file. >> cron.log 2>&1 ghi cả output lẫn lỗi vào file để điều tra. Kiểm tra biểu thức lịch tại crontab.guru trước khi lưu.

Còn cách nào khác?Thư viện schedule hay APScheduler cho phép lên lịch ngay trong một chương trình Python chạy liên tục; hợp khi ứng dụng vốn đã chạy 24/7. Với script chạy rồi thoát, dùng lịch của hệ điều hành đơn giản và bền hơn: máy khởi động lại vẫn chạy, script lỗi lần này không ảnh hưởng lần sau. Trên máy chủ đám mây, GitHub Actions cũng có thể chạy theo lịch (chặng 10).

Tóm tắt

  • subprocess.run([...], capture_output=True, text=True, timeout=..., check=...); lệnh dạng list; tránh shell=True.
  • Script không giám sát: đường dẫn tuyệt đối từ __file__, log ra file, mã thoát đúng, chạy lại được, không hỏi.
  • Windows: schtasks /Create hoặc Task Scheduler; Linux: crontab -e; luôn dùng Python trong .venv bằng đường dẫn tuyệt đối.

Bài tập

Bài 1. Sao lưu giữ 7 bản

Chạy hàm sao_luu 9 lần liên tiếp trên một thư mục mẫu (truyền thời điểm khác nhau mỗi lần) và xác nhận chỉ còn 7 file zip mới nhất.

Xem đáp án 
import logging
import shutil
from datetime import datetime, timedelta
from pathlib import Path

log = logging.getLogger("sao_luu")


def sao_luu(nguon: Path, dich: Path, giu: int, bay_gio: datetime) -> Path:
    dich.mkdir(parents=True, exist_ok=True)
    file_zip = Path(shutil.make_archive(str(dich / f"{nguon.name}_{bay_gio:%Y%m%d_%H%M%S}"), "zip", root_dir=nguon))
    for cu in sorted(dich.glob(f"{nguon.name}_*.zip"))[:-giu]:
        cu.unlink()
    return file_zip


nguon = Path("tai_lieu")
nguon.mkdir(exist_ok=True)
(nguon / "ghi_chu.txt").write_text("dữ liệu quan trọng", encoding="utf-8")
t0 = datetime(2026, 10, 20, 18, 0)
for i in range(9):
    sao_luu(nguon, Path("ban_sao"), 7, t0 + timedelta(days=i))
cac_file = sorted(p.name for p in Path("ban_sao").iterdir())
print(len(cac_file), cac_file[0], cac_file[-1])
7 tai_lieu_20261022_180000.zip tai_lieu_20261028_180000.zip

Truyền bay_gio làm tham số (thay vì gọi datetime.now() bên trong) giúp mô phỏng 9 ngày trong một giây. Đây là lần thứ ba bạn gặp kỹ thuật này: nó chính là điều làm code dễ test.

Bài 2. Lên lịch thật

Lên lịch chạy sao_luu.py lúc 18:00 hằng ngày trên máy của bạn (Task Scheduler hoặc cron), chạy thử ngay một lần bằng lệnh, rồi kiểm tra file log và file zip.

Xem gợi ý

Nếu chạy tay được mà chạy theo lịch không ra gì, 90% là do đường dẫn: kiểm tra sao_luu.log có được tạo cạnh script không (nhờ GOC), và đường dẫn tới python.exe trong lệnh lịch có đúng là của .venv không. Trên Windows, cột "Last Run Result" trong Task Scheduler hiện mã thoát (0x0 là thành công, 0x1 là script trả 1).

Nguồn tham khảo: subprocess; shutil: Archiving operations; Microsoft Learn: schtasks create; crontab(5).

Bài tập thực hành

  1. Viết script sao lưu nén một thư mục thành file zip có ngày giờ trong tên, giữ 7 bản mới nhất.
  2. Lên lịch chạy script sao lưu lúc 18:00 hằng ngày và kiểm tra log sau lần chạy đầu.

Làm xong bài tập mới chuyển sang bài tiếp theo: tự viết code là cách duy nhất để nhớ lâu.
