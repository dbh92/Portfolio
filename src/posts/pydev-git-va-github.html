Không có công ty phần mềm nào làm việc mà không có hệ thống quản lý phiên bản. Git ghi lại mọi thay đổi của code, cho phép quay lại bất kỳ thời điểm nào, thử nghiệm trên nhánh riêng và làm việc cùng người khác mà không ghi đè lên nhau. GitHub là nơi lưu kho Git trên mạng, đồng thời là portfolio của lập trình viên. Bài này dạy đúng những gì bạn dùng hằng ngày.

1. Cài đặt và cấu hình một lần

$ git --version
$ git config --global user.name "Nguyễn Văn An"
$ git config --global user.email "an@example.com"
$ git config --global init.defaultBranch main

Windows: cài từ git-scm.com (giữ lựa chọn mặc định). Tên và email gắn vào mọi commit; dùng email trùng với tài khoản GitHub để commit hiện đúng người.

2. Ba vùng của Git

Thư mục làm việc  --git add-->  Vùng chuẩn bị (staging)  --git commit-->  Lịch sử (.git)

Bạn sửa file trong thư mục làm việc, chọn những thay đổi muốn ghi bằng git add, rồi chốt thành một commit (ảnh chụp có lời nhắn) bằng git commit. Vùng chuẩn bị cho phép chia một loạt thay đổi thành nhiều commit có nghĩa.

3. Vòng làm việc hằng ngày

$ cd thu-vien
$ git init                         # tạo kho (uv init đã làm sẵn bước này)
$ git status                       # xem gì đã đổi: lệnh dùng nhiều nhất
$ git add thu_vien.py README.md    # chọn file
$ git add .                        # hoặc mọi thay đổi (kiểm tra git status trước!)
$ git commit -m "Thêm lớp ThuVien với mượn, trả sách"
$ git log --oneline                # xem lịch sử ngắn gọn
a1b2c3d (HEAD -> main) Thêm lớp ThuVien với mượn, trả sách
$ git diff                         # xem chi tiết thay đổi chưa add
$ git diff --staged                # thay đổi đã add, sắp commit

Một commit tốt chứa một thay đổi có nghĩa và lời nhắn nói rõ "làm gì": "Sửa lỗi tính quá hạn khi trả đúng ngày" tốt hơn nhiều so với "update" hay "sửa". Commit thường xuyên, mỗi khi xong một bước nhỏ chạy được.

4. .gitignore cho dự án Python

File .gitignore ở gốc dự án liệt kê những gì Git bỏ qua. Với Python, tối thiểu:

# môi trường và bộ nhớ đệm
.venv/
__pycache__/
*.pyc
.pytest_cache/
.mypy_cache/
.ruff_cache/
.coverage
htmlcov/
# build
dist/
build/
*.egg-info/
# bí mật và dữ liệu cục bộ
.env
*.log
*.db
Không bao giờ commit mật khẩu, API keyĐặt bí mật trong file .env (đã nằm trong .gitignore) và đọc bằng biến môi trường. Một khi key đã lên GitHub, coi như đã lộ, kể cả khi bạn xóa commit sau đó: có các bot quét GitHub liên tục để tìm key. Lỡ đẩy lên rồi thì thu hồi key ngay ở nhà cung cấp và tạo key mới.

5. Hoàn tác thường gặp

$ git restore thu_vien.py          # bỏ thay đổi chưa add của file (MẤT thay đổi đó)
$ git restore --staged thu_vien.py # bỏ khỏi vùng chuẩn bị, giữ thay đổi
$ git commit --amend -m "Lời nhắn mới"   # sửa commit cuối (khi CHƯA push)
$ git revert a1b2c3d               # tạo commit mới đảo ngược một commit cũ (an toàn khi đã push)

6. Đưa lên GitHub

Tạo kho mới trên GitHub (nút New repository, không tích tạo README vì bạn đã có), rồi:

$ git remote add origin https://github.com/ten-ban/thu-vien.git
$ git push -u origin main          # lần đầu; sau đó chỉ cần: git push
$ git pull                         # lấy thay đổi mới từ GitHub về

Lần đầu push, Git trên Windows mở cửa sổ đăng nhập GitHub qua trình duyệt (Git Credential Manager). Một cách khác tiện cho cả máy Linux: cài GitHub CLI và chạy gh auth login. GitHub không còn nhận mật khẩu tài khoản khi push qua HTTPS.

7. Nhánh và pull request

Không ai sửa thẳng trên main ở công ty. Mỗi tính năng, mỗi lần sửa lỗi làm trên một nhánh riêng, rồi mở pull request (PR) để đồng nghiệp xem lại trước khi gộp.

$ git switch -c them-tim-kiem       # tạo nhánh mới và chuyển sang
  ... sửa code, git add, git commit ...
$ git push -u origin them-tim-kiem
  → GitHub hiện nút "Compare & pull request": viết mô tả, tạo PR
  → đồng nghiệp xem, góp ý; bạn sửa và push thêm commit vào nhánh
  → bấm "Merge pull request"
$ git switch main
$ git pull                          # lấy main mới đã có tính năng
$ git branch -d them-tim-kiem       # xóa nhánh đã gộp

Khi hai người sửa cùng một dòng, Git báo xung đột (conflict) và đánh dấu trong file:

<<<<<<< HEAD
SO_NGAY_MUON = 14
=======
SO_NGAY_MUON = 21
>>>>>>> them-gia-han

Sửa file thành nội dung đúng (xóa các dòng đánh dấu), rồi git add và git commit. VS Code có nút "Accept Current / Incoming / Both" giúp việc này dễ hơn.

GitHub là CV của bạnNhà tuyển dụng Python Developer thường xem GitHub trước khi xem CV. Vài dự án có README rõ ràng, lịch sử commit đều đặn, có test và CI (chặng 10) có sức nặng hơn nhiều so với một danh sách kỹ năng.

Tóm tắt

  • git status → git add → git commit -m "..."; commit nhỏ, lời nhắn rõ.
  • .gitignore loại .venv, cache, .env; không bao giờ commit bí mật.
  • git remote add origin ..., git push -u origin main, git pull.
  • Mỗi tính năng một nhánh git switch -c, gộp qua pull request.

Bài tập

Bài 1. Đưa dự án thư viện lên GitHub

Đưa dự án quản lý thư viện ở chặng 4 lên GitHub với .gitignore đúng và README.md có mô tả, cách chạy.

Xem gợi ý

Trước khi commit lần đầu, chạy git status và kiểm tra không có .venv/, __pycache__/ hay thu_vien.json chứa dữ liệu thật trong danh sách. README tối thiểu: một câu mô tả, yêu cầu (Python 3.12+), lệnh chạy, ví dụ kết quả. Sau khi push, mở trang kho trên GitHub và đọc lại README như một người lạ.

Bài 2. Nhánh và pull request

Tạo nhánh them-tim-kiem, thêm tính năng tìm sách theo năm xuất bản (hoặc tính năng tùy ý), mở pull request và tự gộp vào main.

Xem gợi ý

Trong mô tả PR, viết ba phần: Làm gì, Vì sao, Kiểm tra thế nào. Đây là thói quen được đánh giá cao ở mọi nhóm phát triển. Sau khi gộp, chạy git log --oneline --graph trên main để thấy commit của nhánh đã vào lịch sử.
