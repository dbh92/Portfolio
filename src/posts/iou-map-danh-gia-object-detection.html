1. IoU: hai hộp trùng nhau bao nhiêu

IoU (Intersection over Union) là diện tích phần giao chia cho diện tích phần hợp của hai hộp:

IoU = S(A ∩ B) / S(A ∪ B) = S(A ∩ B) / (S(A) + S(B) − S(A ∩ B))

IoU = 1 khi hai hộp trùng khít, 0 khi không chạm nhau. Hộp viết dạng (x1, y1, x2, y2) theo pixel, tọa độ liên tục (rộng = x2 − x1, không cộng 1; một số code cũ của Pascal VOC cộng 1, đừng trộn hai quy ước). Đây là bài thực hành của bài: viết hàm và kiểm tra với các cặp hộp đã tính tay.

def iou(a, b):
    """a, b: (x1, y1, x2, y2). Trả về IoU trong [0, 1]."""
    rong = max(0.0, min(a[2], b[2]) - max(a[0], b[0]))      # bề rộng phần giao (0 nếu không giao)
    cao = max(0.0, min(a[3], b[3]) - max(a[1], b[1]))
    giao = rong * cao
    hop = (a[2] - a[0]) * (a[3] - a[1]) + (b[2] - b[0]) * (b[3] - b[1]) - giao
    return giao / hop if hop > 0 else 0.0

Khi đánh giá, ta cần IoU giữa mọi dự đoán và mọi nhãn thật. Viết bằng phép toán mảng (broadcasting) nhanh hơn vòng lặp hàng trăm lần, và kiểm tra chéo với torchvision.ops.box_iou:

import numpy as np
import torch
from torchvision.ops import box_iou


def iou_ma_tran(A, B):
    """A: (N, 4), B: (M, 4) → ma trận IoU (N, M)."""
    A, B = np.asarray(A, float)[:, None], np.asarray(B, float)[None]
    rong = (np.minimum(A[..., 2], B[..., 2]) - np.maximum(A[..., 0], B[..., 0])).clip(0)
    cao = (np.minimum(A[..., 3], B[..., 3]) - np.maximum(A[..., 1], B[..., 1])).clip(0)
    giao = rong * cao
    dt = lambda X: (X[..., 2] - X[..., 0]) * (X[..., 3] - X[..., 1])
    return giao / (dt(A) + dt(B) - giao)

2. NMS: bỏ các hộp trùng lặp

Đa số mô hình phát hiện (YOLOv8, YOLO11, Faster R-CNN…) dự đoán nhiều hộp chồng lên nhau cho cùng một vật. NMS (Non-Maximum Suppression) dọn dẹp: sắp xếp hộp theo điểm tin cậy giảm dần, giữ hộp cao nhất, bỏ mọi hộp cùng lớp có IoU với nó vượt ngưỡng (thường 0,45–0,7), lặp lại với các hộp còn lại. YOLO26 là mô hình end-to-end, tự học cách chỉ trả một hộp cho mỗi vật nên không cần bước này; nhưng bạn vẫn gặp NMS khi dùng các mô hình khác, khi ghép kết quả từ nhiều ô ảnh (tiling) chồng lấn, và khi đọc code triển khai cũ.

import numpy as np
import torch
from torchvision.ops import nms


def nms_numpy(hop, diem, nguong_iou=0.5):
    """Trả về chỉ số các hộp được giữ, theo thứ tự điểm giảm dần (một lớp)."""
    thu_tu = np.argsort(-diem)
    giu = []
    while len(thu_tu):
        i = thu_tu[0]
        giu.append(int(i))
        con_lai = thu_tu[1:]
        thu_tu = con_lai[iou_ma_tran(hop[[i]], hop[con_lai])[0] <= nguong_iou]
    return giu


hop = np.array([[100, 100, 140, 140], [102, 98, 143, 141], [97, 103, 138, 139],    # 3 hộp cho 1 con vít
                [300, 120, 340, 160], [305, 125, 345, 165]], float)               # 2 hộp cho con vít khác
diem = np.array([0.91, 0.88, 0.62, 0.75, 0.80])
print("NumPy      giữ:", nms_numpy(hop, diem, 0.5))
print("torchvision giữ:", nms(torch.tensor(hop), torch.tensor(diem), 0.5).tolist())

Còn đúng hai hộp, một cho mỗi vít. Ngưỡng IoU của NMS là một tham số thật sự: quá thấp thì hai vật sát nhau (vít trong khay xếp khít) bị gộp làm một, quá cao thì một vật ra hai hộp và bị đếm hai lần.

3. Ghép dự đoán với nhãn thật: TP, FP, FN

Để chấm điểm, mỗi dự đoán được ghép với tối đa một nhãn thật theo quy tắc (giống COCO):

  1. Xét từng lớp riêng. Sắp các dự đoán của lớp đó (trên toàn bộ tập ảnh) theo điểm tin cậy giảm dần.
  2. Với mỗi dự đoán, tìm trong cùng ảnh nhãn thật cùng lớp chưa được ghép có IoU lớn nhất. Nếu IoU ≥ ngưỡng (ví dụ 0,5): TP (True Positive), đánh dấu nhãn đó đã ghép. Nếu không: FP (False Positive).
  3. Nhãn thật không được dự đoán nào ghép: FN (False Negative, bỏ sót).

Hệ quả: hộp trùng lặp cho một vật đã có TP sẽ thành FP; hộp đúng vị trí nhưng sai lớp là FP của lớp này và để lại FN ở lớp kia. Tập dữ liệu nhỏ dưới đây (3 ảnh, 2 lớp như bài trước) được thiết kế để có đủ các tình huống: hộp tốt, hộp lệch, hộp trùng, báo nhầm trên nền, bỏ sót.

import numpy as np

TEN = {0: "vit", 1: "dai_oc"}
# nhãn thật: (ảnh, lớp, x1, y1, x2, y2)
GT = [(1, 0, 10, 10, 50, 50), (1, 0, 100, 20, 140, 60), (1, 1, 200, 100, 250, 150),
      (2, 0, 30, 30, 70, 70), (2, 1, 120, 80, 170, 130), (2, 1, 220, 40, 270, 90),
      (3, 0, 50, 100, 90, 140), (3, 0, 150, 150, 190, 190)]
# dự đoán: (ảnh, lớp, điểm, x1, y1, x2, y2)
PRED = [(1, 0, .95, 11, 11, 51, 49), (1, 0, .80, 104, 22, 146, 62), (1, 0, .40, 12, 8, 52, 50),
        (1, 1, .90, 202, 103, 252, 148),
        (2, 0, .85, 36, 36, 76, 76), (2, 1, .70, 121, 82, 168, 131), (2, 1, .30, 300, 10, 340, 50),
        (3, 0, .60, 50, 100, 90, 140), (3, 0, .55, 160, 160, 200, 200), (3, 0, .35, 250, 20, 280, 50)]


def ghep(lop, nguong_iou):
    """Trả về (điểm, cờ TP, IoU tốt nhất) của các dự đoán lớp `lop` theo điểm giảm dần, và số nhãn thật."""
    gt = [g for g in GT if g[1] == lop]
    pr = sorted([p for p in PRED if p[1] == lop], key=lambda p: -p[2])
    da_ghep = [False] * len(gt)
    diem, tp, iou_tot = [], [], []
    for anh, _, s, *hop in pr:
        ung_vien = [(iou(hop, g[2:]), k) for k, g in enumerate(gt) if g[0] == anh and not da_ghep[k]]
        v, k = max(ung_vien, default=(0.0, -1))
        la_tp = v >= nguong_iou
        if la_tp:
            da_ghep[k] = True
        diem.append(s); tp.append(la_tp); iou_tot.append(v)
    return np.array(diem), np.array(tp), np.array(iou_tot), len(gt)

4. Precision, recall theo ngưỡng tin cậy và đường cong PR

Mỗi dòng của bảng trên tương ứng với một ngưỡng tin cậy: đặt ngưỡng bằng điểm của dòng đó thì chỉ các dự đoán từ dòng đầu đến dòng đó được giữ lại.

  • Precision = TP / (TP + FP): trong các hộp mô hình báo, bao nhiêu phần là đúng. Precision thấp = báo nhầm nhiều.
  • Recall = TP / số nhãn thật: trong các vật thật, bao nhiêu phần được tìm thấy. Recall thấp = bỏ sót nhiều.

Hạ ngưỡng thì recall chỉ tăng hoặc giữ nguyên, precision thường giảm. Vẽ các cặp (recall, precision) được đường cong PR. Ở bảng trên, ngưỡng 0,60 cho precision 1,0 và recall 0,8; hạ xuống 0,35 recall không tăng thêm (vít thứ năm bị hộp lệch, không hộp nào ghép được) mà precision rơi xuống 0,57. Cách chọn ngưỡng theo các con số này (và theo chi phí của nhà máy) đã học ở bài "Precision, Recall và ma trận nhầm lẫn" của chặng 5.

5. AP và mAP50

AP (Average Precision) tóm tắt cả đường cong PR của một lớp thành một số: diện tích dưới đường cong, sau khi làm "phẳng" đường cong bằng cách thay precision ở mỗi mức recall bằng precision lớn nhất ở mọi mức recall lớn hơn hoặc bằng (bao trên, envelope). Hai cách tính phổ biến:

  • Nội suy toàn điểm (Pascal VOC từ 2010): cộng diện tích các bậc thang của bao trên.
  • Nội suy 101 điểm (COCO): lấy trung bình precision của bao trên tại 101 mức recall 0; 0,01; …; 1.

Mức recall chưa đạt được (ở đây trên 0,8) có precision 0, nên bỏ sót làm AP giảm trực tiếp. mAP là trung bình AP của các lớp; mAP50 là mAP khi ngưỡng IoU để tính TP là 0,5.

import numpy as np


def ap_tu_pr(P, R, cach="toan_diem"):
    r = np.concatenate([[0.0], R, [1.0]])
    p = np.concatenate([[1.0], P, [0.0]])
    p = np.maximum.accumulate(p[::-1])[::-1]                     # bao trên: precision không tăng theo recall
    if cach == "toan_diem":
        i = np.where(r[1:] != r[:-1])[0]
        return float(np.sum((r[i + 1] - r[i]) * p[i + 1]))
    muc = np.linspace(0, 1, 101)                                 # COCO 101 điểm
    chi_so = np.searchsorted(r, muc, side="left")                # điểm đầu tiên có recall ≥ mức
    return float(np.mean([p[k] if k < len(p) else 0.0 for k in chi_so]))


def ap_lop(lop, nguong_iou, cach="toan_diem"):
    s, tp, _, n_gt = ghep(lop, nguong_iou)
    tp_cum, fp_cum = np.cumsum(tp), np.cumsum(~tp)
    return ap_tu_pr(tp_cum / (tp_cum + fp_cum), tp_cum / n_gt, cach)


for cach in ("toan_diem", "101_diem"):
    ap = {TEN[k]: ap_lop(k, 0.5, cach) for k in TEN}
    print(f"{cach:9s}: AP50 " + ", ".join(f"{t} = {v:.4f}" for t, v in ap.items())
          + f" → mAP50 = {np.mean(list(ap.values())):.4f}")

Kiểm tra bằng tay lớp vit: bao trên có precision 1,0 từ recall 0 đến 0,8, rồi 0 sau đó; diện tích = 0,8 × 1,0 = 0,8. Cách 101 điểm cho 81/101 ≈ 0,802 vì đếm cả mức recall 0 và 0,8. Lớp dai_oc: precision 1,0 đến recall 2/3, AP ≈ 0,667. Các thư viện khác nhau dùng cách nội suy và quy tắc ghép hơi khác nhau, nên cùng một tập dự đoán có thể cho mAP lệch nhau ở chữ số thập phân thứ hai hoặc thứ ba. Chỉ so sánh mAP tính bằng cùng một công cụ, trên cùng một tập dữ liệu.

Kiểm tra chéo với scikit-learn: average_precision_score tính AP không nội suy (Σ ΔR·P tại mỗi TP) trên các dự đoán đã có, nên chỉ cần nhân thêm tỉ lệ nhãn thật được tìm thấy:

import numpy as np
from sklearn.metrics import average_precision_score

for lop in TEN:
    s, tp, _, n_gt = ghep(lop, 0.5)
    tp_cum, fp_cum = np.cumsum(tp), np.cumsum(~tp)
    P, R = tp_cum / (tp_cum + fp_cum), tp_cum / n_gt
    ap_tay = float(np.sum(np.diff(np.r_[0, R]) * P))                     # không nội suy
    ap_sk = average_precision_score(tp, s) * tp.sum() / n_gt
    print(f"{TEN[lop]:7s}: tự tính {ap_tay:.4f} | scikit-learn {ap_sk:.4f}")

6. mAP50-95: đòi hỏi hộp khít

mAP50 chỉ cần hộp trùng một nửa. mAP50-95 (COCO gọi là AP, Ultralytics ghi mAP50-95) lấy trung bình mAP ở 10 ngưỡng IoU 0,50; 0,55; …; 0,95. Hộp phải khít mới giữ được TP ở ngưỡng cao:

8. Chẩn đoán mô hình từ chỉ số

Để thấy mỗi "bệnh" để lại dấu vết gì trên các chỉ số, ta mô phỏng một tập kiểm tra 300 ảnh vết móp (150 ảnh OK không có lỗi, 150 ảnh NG có 1–2 vết, cỡ 20–60 px) và bốn mô hình giả lập: A tốt; B tìm đúng vật nhưng hộp lỏng lẻo (lệch trung bình 12% kích thước); C bỏ sót 35% vết; D báo nhầm nhiều trên nền. Chỉ số tính bằng các hàm vừa viết.

import numpy as np


def mo_phong(p_thay, lech, p_bao_nham, seed=0):
    rng = np.random.default_rng(seed)
    gt, pred = [], []
    for anh in range(300):
        for _ in range(0 if anh < 150 else int(rng.integers(1, 3))):
            x, y, c = rng.uniform(0, 400), rng.uniform(0, 400), rng.uniform(20, 60)
            gt.append((anh, 0, x, y, x + c, y + c))
            if rng.random() < p_thay:
                d = rng.normal(0, lech * c, 4)
                pred.append((anh, 0, rng.uniform(0.6, 0.99), x + d[0], y + d[1], x + c + d[2], y + c + d[3]))
        if rng.random() < p_bao_nham:                       # báo nhầm trên nền
            x, y, c = rng.uniform(0, 400), rng.uniform(0, 400), rng.uniform(20, 60)
            pred.append((anh, 0, rng.uniform(0.3, 0.9), x, y, x + c, y + c))
    return gt, pred


def danh_gia(gt, pred, nguong_conf=0.5):
    global GT, PRED
    GT, PRED = gt, pred                                      # dùng lại hàm ghep() ở trên
    ap = [ap_lop(0, t) for t in np.round(np.arange(0.5, 0.96, 0.05), 2)]
    s, tp, _, n_gt = ghep(0, 0.5)
    giu = s >= nguong_conf
    P, R = tp[giu].sum() / max(giu.sum(), 1), tp[giu].sum() / n_gt
    co_loi = {g[0] for g in gt}                               # ảnh NG
    bao_ng = {p[0] for p in pred if p[2] >= nguong_conf}      # ảnh có ít nhất 1 hộp ≥ ngưỡng
    escape = len(co_loi - bao_ng) / len(co_loi)
    overkill = len(bao_ng - co_loi) / (300 - len(co_loi))
    return P, R, ap[0], float(np.mean(ap)), escape, overkill

Hai cột cuối là ngôn ngữ của nhà máy: ở ngưỡng 0,5, ảnh NG không có hộp nào là escape (lọt lỗi), ảnh OK có hộp là overkill (loại nhầm). Mô hình B có mAP50-95 tệ nhất nhưng escape và overkill như mô hình A: nếu trạm chỉ cần biết "có vết móp hay không", hộp lỏng không phải vấn đề. Mô hình C có precision gần như mô hình A, nhưng lọt khoảng một phần tư số ảnh lỗi, không thể chấp nhận. Mô hình D không lọt ảnh lỗi nào nhưng loại nhầm một phần tư số sản phẩm tốt. Đó là lý do báo cáo cho nhà máy phải là escape, overkill ở ngưỡng chạy thật, trên tập test đủ lớn, kèm số mẫu (bài "Chọn ngưỡng và đánh giá theo escape, overkill, cycle time"); mAP dùng để so sánh mô hình trong lúc phát triển.

9. Sai lầm thường gặp

  • So mAP giữa hai công cụ (Ultralytics, pycocotools, code tự viết) hoặc giữa hai tập val khác nhau: cách nội suy và ghép khác nhau làm lệch kết quả.
  • Báo cáo mAP50 cho bài toán định vị cần độ chính xác vị trí: hộp lệch 40% vẫn là TP ở IoU 0,5.
  • Đọc P, R của Ultralytics như thể ở ngưỡng sản xuất.
  • Lấy ngưỡng NMS quá thấp khi vật xếp sát nhau: vật bị gộp, đếm thiếu.
  • Đánh giá vật nhỏ bằng IoU 0,5 mà không xem ảnh: vài pixel sai lệch nhãn đủ biến TP thành FP + FN.
  • Quên ảnh OK trong tập đánh giá: mAP chỉ tính trên các vật có thật, không phản ánh overkill trên ảnh sạch nếu tập test ít ảnh nền.

10. Bài tập

Bài 1. (Thực hành của bài) Dùng hàm iou ở mục 1, tính IoU cho ba cặp hộp sau, so với kết quả tính tay: (a) (0, 0, 40, 40) và (20, 0, 60, 40); (b) (10, 10, 110, 60) và (10, 10, 60, 110); (c) (0, 0, 50, 50) và (0, 0, 25, 25).

Xem đáp án

Tính tay: (a) giao 20×40 = 800, hợp 1600 + 1600 − 800 = 2400, IoU = 1/3. (b) giao 50×50 = 2500, mỗi hộp 100×50 = 5000, hợp 7500, IoU = 1/3. (c) hộp nhỏ nằm trong: 625 / 2500 = 0,25.

cap = [((0, 0, 40, 40), (20, 0, 60, 40), 800 / 2400),
       ((10, 10, 110, 60), (10, 10, 60, 110), 2500 / 7500),
       ((0, 0, 50, 50), (0, 0, 25, 25), 625 / 2500)]
for a, b, tay in cap:
    print(f"{a} vs {b}: {iou(a, b):.4f} (tay {tay:.4f})", "khớp" if abs(iou(a, b) - tay) < 1e-9 else "SAI")
(0, 0, 40, 40) vs (20, 0, 60, 40): 0.3333 (tay 0.3333) khớp
(10, 10, 110, 60) vs (10, 10, 60, 110): 0.3333 (tay 0.3333) khớp
(0, 0, 50, 50) vs (0, 0, 25, 25): 0.2500 (tay 0.2500) khớp

Cặp (b) đáng nhớ: hai hộp cùng diện tích, cùng góc trên trái, chỉ xoay hướng dài, IoU chỉ còn 1/3. Đó là lý do vật dài, mảnh và nghiêng (vết xước chéo) đánh giá bằng hộp thẳng rất kém; bài sau giới thiệu phân đoạn.

Bài 2. Một lớp có 4 nhãn thật. Năm dự đoán theo điểm giảm dần có kết quả TP, FP, TP, TP, FP. Tính precision, recall sau mỗi dự đoán và AP (nội suy toàn điểm) bằng tay, rồi kiểm tra bằng ap_tu_pr.

Xem đáp án

TP tích lũy 1, 1, 2, 3, 3; FP tích lũy 0, 1, 1, 1, 2. Precision 1; 0,5; 0,667; 0,75; 0,6. Recall 0,25; 0,25; 0,5; 0,75; 0,75. Bao trên: precision 1 đến recall 0,25; 0,75 từ 0,25 đến 0,75; sau đó 0. AP = 0,25 × 1 + 0,5 × 0,75 = 0,625.

import numpy as np

tp = np.array([1, 0, 1, 1, 0], bool)
tc, fc = np.cumsum(tp), np.cumsum(~tp)
print("AP =", round(ap_tu_pr(tc / (tc + fc), tc / 4), 4))
AP = 0.625

Bài 3. Hai mô hình phát hiện vết lỗi trên cùng tập val: M1 có mAP50 0,91, mAP50-95 0,52, P 0,93, R 0,78; M2 có mAP50 0,88, mAP50-95 0,66, P 0,80, R 0,90. Trạm chỉ cần loại sản phẩm có lỗi (không đo kích thước), khách hàng ưu tiên không lọt lỗi. Chọn mô hình nào để thử tiếp, và cần đo thêm gì trước khi quyết định?

Xem đáp án

M2 đáng thử hơn: recall cao hơn (bỏ sót ít hơn) quan trọng nhất khi ưu tiên không lọt lỗi; mAP50-95 của M1 thấp cho thấy hộp kém khít nhưng điều đó không quan trọng với trạm chỉ cần có/không. Precision thấp của M2 có thể bù bằng chọn ngưỡng hoặc thêm ảnh nền. Tuy nhiên P, R in ra ở ngưỡng do thư viện chọn, nên phải: (1) tính escape và overkill cấp ảnh của cả hai mô hình theo nhiều ngưỡng trên tập test có đủ ảnh OK và NG; (2) chọn ngưỡng cho escape bằng 0 (hoặc ≤ mức khách cho phép) rồi so overkill tại đó; (3) kiểm tra cycle time. Quyết định theo kết quả đó, không theo mAP.

Tóm tắt

  • IoU = giao / hợp; khắt khe với vật nhỏ (lệch 2 px trên vật 8 px còn 0,39); tính dạng ma trận để nhanh, kiểm tra chéo với torchvision.ops.box_iou.
  • NMS giữ hộp điểm cao nhất, bỏ hộp trùng có IoU vượt ngưỡng; YOLO26 end-to-end không cần NMS nhưng bạn vẫn gặp nó ở mô hình khác và khi ghép ô ảnh.
  • Ghép dự đoán theo điểm giảm dần với nhãn thật chưa ghép có IoU lớn nhất: TP, FP, FN; hộp trùng là FP.
  • Precision, recall thay đổi theo ngưỡng tin cậy; AP là diện tích dưới bao trên của đường PR (toàn điểm hoặc 101 điểm); mAP là trung bình các lớp.
  • mAP50 dễ dãi về vị trí; mAP50-95 đòi hộp khít. Chẩn đoán: mAP50-95 ≪ mAP50 là hộp lỏng; R thấp là bỏ sót; P thấp là báo nhầm.
  • mAP để so mô hình; nhà máy cần escape, overkill cấp ảnh ở ngưỡng chạy thật.

Bài tiếp theo: Phân đoạn ảnh: semantic, instance, panoptic, khi hộp bao không đủ và cần biết chính xác từng pixel thuộc vết lỗi nào.
